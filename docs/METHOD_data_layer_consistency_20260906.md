## 驗收

1. partial/empty/wrong-date、缺週、子程序失敗 fixture 必须能抓到真錯誤。
2. 真實來源以明確資料日期、列數、欄位/語意與官方證據驗證；成功、無法取得及非交易狀態分列。
3. 正式模型/selection/pin、rere 規則、預測及帳本 SHA 在不需要重產的範圍保持一致。
4. 必要資料寫入採原子替換，DB 使用正式 release/transaction/reconnect 流程，回查 API。
5. 分項 commit，交付具體已補數量、仍缺原因、服務驗收及完整提交清單。
