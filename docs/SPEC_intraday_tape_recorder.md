# SPEC(草案,未核可)— 盤中五檔/成交記錄器(Intraday Tape Recorder)

> 狀態:**DRAFT,待 PM 核可後才開工**。起因:2026-10-01 rere 南茂盤中加碼案例
> (`docs/rere_strategy.md` 同日條目)——她靠群組盤中判讀「五檔大單被吃、價不退」加碼,
> 系統現有 `scripts/intraday_quote.py` 只能抓單一瞬間,看不到連續過程。
> 定位:**練習/校準工具,不是訊號產生器**。側寫既有結論不變:盤感機械化無 edge。

## 1. 目的與非目的

- 目的:把觀察名單的盤中五檔與成交連續存下來,收盤後產出「吸收/出貨」事後摘要,
  讓用戶的盤中判斷可以對答案(法人、分點截圖、後續 3-5 日走勢)。
- 非目的:不產生進出場訊號、不改名單、不進模型特徵、不下單。升級為盤中提醒需另案回測+PM 核可。

## 2. 資料來源與實測限制(2026-10-02 00:20 live payload 驗證)

- TWSE MIS `getStockInfo.jsp`,一個請求可混查多檔上市/上櫃(`tse_8150.tw|otc_6532.tw` 實測可)。
- 伺服器回 `userDelay: 5000` → **輪詢間隔 5 秒**,不得更密(同 IP 還有 `intraday_quote.py` 共用額度)。
- 可用欄位(實測):`z` 成交價、`tv` 最近一筆量、`v` 累計量、`a`/`f` 賣五檔價/量、`b`/`g` 買五檔價/量、
  `t`/`tlong` 時間、`y` 昨收、`u`/`w` 漲跌停、`o`/`h`/`l`。
- **限制(必須寫在報表上)**:MIS 是 5 秒快照,不是逐筆。兩次快照之間的多筆成交只看得到 Δ`v`;
  內外盤只能用「成交價對前一張快照的買一/賣一」近似;撤單與成交無法完全區分。
  鎖死盤 `z='-'`、單邊五檔空的怪癖沿用 `intraday_quote.py` 既有處理。
- 替代方案 B(品質高一級):券商 API 的逐筆+五檔串流(需用戶自行申請與登入,憑證不得由 agent 輸入)。
  先做 MIS 版,欄位設計保留 `source` 以便日後換源。

## 3. 隔離與紅線(最重要)

AGENTS.md 紅線 #2 寫「盤中不啟動 Phase-1/twstock/**任何抓取**」,立意是防止未收盤假棒寫入日K。
本記錄器是盤中抓取,**落地前必須由 PM 核可並在 AGENTS.md 明文加例外**,條件:

1. 只寫 `logs/tape/YYYYMMDD/`(`logs/` 已 gitignore)——**永不寫** `日K資料/`、`stock.duckdb`、
   任何 git 追蹤檔、任何憑證來源檔;不 import `twstock.py` / ingest / smart_update 的寫入路徑。
2. 獨立程序名 `intraday_tape_recorder`(不命中 preflight 的 pipeline 程序鍵);不取 pipeline 鎖。
3. 測試須證明:執行前後 `git status` 無變化、日K CSV 與 DuckDB mtime 不變。
4. 非交易日(`is_taiwan_trading_day`)與 09:00 前/13:35 後自動結束;單次請求失敗只記錄不重試風暴。

## 4. 架構(三段)

### P0 記錄器 `scripts/intraday_tape_recorder.py`
- 標的:`logs/entry_watchlist.json` + 當日 canonical 名單 rere 列 + 選配「我的持股」(見 §6 決策 1);
  上限 30 檔(單請求)。
- 存檔:`logs/tape/YYYYMMDD/<ticker>.jsonl`,每列一張快照(只在內容有變時寫入);另存 `_meta.json`
  (起訖時間、快照數、失敗數、source)。
- 排程:Windows 工作排程 平日 08:55 啟動,13:35 自行結束。

### P1 收盤後摘要 `scripts/tape_summary.py`(Phase-1 之外獨立跑,14:35 後)
每檔輸出(全部附「5 秒快照近似」註記):
- 外盤比(近似)、分時段量能(09:00-09:30 / 盤中 / 尾盤)
- 大單成交次數與方向(門檻見 §6 決策 2)
- **吸收事件**:賣一(或買一)大量在 N 張快照內被消耗且價格未跌(未漲)破該價
- **殺低不破**:創日低後 M 分鐘未再破、其後量縮回升幅度
- **掛單異動未成交**:五檔大單出現又消失而 Δ`v` 不相稱(疑似假掛單,僅標示)
- 相對位置:收盤 vs VWAP、vs watch 卡區間/失效價
產物:`logs/tape/YYYYMMDD/summary.json` + 一頁 HTML;是否進儀表板另議(進了就要走 dashboard-interface-update)。

### P2 校準帳本 `logs/tape/calibration_ledger.csv`
- 每個「吸收/出貨」事件一列:日期、標的、事件類型、當時價;T+1 補法人買賣超,T+5 補後續報酬與是否破事件低點。
- 用戶可選填自己的盤中判斷與分點截圖結論(手動欄)。
- 月度小結:事件後 5 日表現 vs 同檔同期無事件日的 base rate。

## 5. Bounded experiment(事前判準,依 feedback_bounded_experiment_kill_criteria)

- 期間:30 個交易日或累積 ≥60 個事件,先到為準。
- 繼續條件:吸收事件後 5 日「不破事件低點」比例明顯高於 base rate(門檻由 PM 事前框定,見 §6 決策 3)。
- 否則:記錄器降為 research-only 封存,不再擴充;**任何情況下**都不因本工具調整既有 gate/名單。
